## Próxima decisão obrigatória

Criar um ADR para escolher frontend e backend antes de implementar a estrutura principal da aplicação. O ADR deve:
- avaliar as necessidades reais do projeto e o estado do repositório;
- comparar alternativas viáveis, incluindo manutenção, hospedagem, segurança, testes e competências disponíveis;
- considerar a recomendação de stack registrada em `docs/PROJECT_RULES.md`, atribuída a Lucas Belucci Bellini e referenciada ao repositório Cosmos;
- explicar se cada tecnologia recomendada é necessária, opcional ou inadequada para este projeto;
- registrar explicitamente a decisão aprovada e as tecnologias descartadas.

Não preencher os campos pendentes com suposições. Uma proposta só passa a ser decisão quando sua aprovação estiver registrada.
